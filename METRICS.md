# Scanly performance metrics

Every number here comes from a real run of `scripts/benchmark.py`. Nothing is estimated.

## Method

- **What's measured:** `POST /api/analyze` on the **local** backend (no Render cold start, no internet hop to Render), one request at a time.
- **Inputs:** 11 fictional resumes generated by `scripts/make_sample_resumes.py` (1–2 pages, varied layouts, one image-only "scanned" PDF), each sent `--passes` times. Same job title and description on every run.
- **total:** end-to-end time measured by the benchmark client. **gemini:** time inside the AI call, from the backend's `Server-Timing` header.
- **median** = typical run; **p90** = 90% of runs were faster (`statistics.quantiles(..., method="inclusive")`, so it never exceeds the slowest observed run).
- **Fallback runs** are runs where the first model was busy and the next one answered; they're reported separately because they mix models.
